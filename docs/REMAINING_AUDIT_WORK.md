## Connected workflows

- **TopoSync / Point Clouds (G01):** inspect LAS/LAZ, retain immutable source, list retained files/hashes and preview a bounded first-record sample. Native LAS metadata needs no optional software. Record preview needs laspy; compressed LAZ needs a compatible decoder or supported external metadata reader. Missing optional support is visible. This is not automatic surface generation, a representative statistical sample or a coordinate transformation.
- **Home and QASync / Project Automation (G02):** create/edit ordered actions, select triggers, enable/disable, save/run, YAML import/export, run history and individual approve/reject controls. Approval is tied to a snapshot of the saved definition. Changed definitions fail closed; in-process serialized approvals prevent double execution. Email/delivery stays explicit and requires configured delivery credentials. YAML replaces definitions only after confirmation; run history is retained.
- **GISSync / CRS Diagnostics (G03):** source/target profiles, project-unit review, operation alternatives/missing grids and optional test coordinate. The actual selected operation also performs the sample transform. No project coordinates are changed. Invalid/partial/non-finite samples and invalid bounding areas fail clearly.
- **ReportSync / Excel Template Mapper (G04):** inspect/retain XLSX/XLSM, select project scalar fields and worksheet/cells, optionally map point-table columns, validate/save mapping, render a new draft workbook and remove mappings without deleting sources. Original formula cells and merged continuations cannot be overwritten. Source text cannot become spreadsheet formulas. Output names are unique; existing output files are never replaced. Excel formula expressions are preserved, not evaluated by openpyxl. Reopen in Excel and check results, especially macro-enabled workbooks and unsupported Excel extensions.
- **GISSync / External GIS Processing (G05):** explicit or detected executable paths, runtime state, QGIS algorithm listing/help, typed parameters and reviewed execution. Existing command-array bridges are used. No automatic third-party install or arbitrary shell textarea. External tools retain normal local account permissions; review output paths and use copies of evidence. Missing engines and nonzero exit results remain visible failures.

Each new project-bound API checks the optional X-SurveySync-Project header from these panels. A panel bound to a different project returns 409 rather than silently writing to the newly opened job. Existing non-panel API callers remain compatible. Each operation captures the selected project; this is not cross-process transactional isolation for shared network projects.

## Build identity and update trust

RELEASE_ID.txt records the installed build identity separately from the numeric version. Both Python and the native launcher compare numeric prerelease identifiers (beta.2 before beta.10); build metadata does not set precedence. Legacy numeric-only manifests remain accepted. The helper verifies the installed release ID after Setup and writes a local completed-install receipt. The updater can recognize promotion of the same verified bytes without an unnecessary reinstall. The old published launcher cannot learn this before upgrading to a future numerically newer candidate. This branch has not been distributed under an existing beta identity.

A signed-manifest verifier and CLI are implemented using Ed25519 with packaged public-key pins and signed expiry. Tampering, unknown keys, expiry and unsigned fallback under required-signature mode fail closed. **Production signing is not activated**: update_trust.json explicitly remains legacy mode and contains no production keys. The optional cryptography dependency must be pinned/provisioned for signed-mode installation; owner-controlled private keys belong outside source in protected CI, never generated and committed by this task. Validating an unsigned hash is not equivalent to publisher authentication.

Windows build hooks can require/sign/verify both launchers and Setup using an owner-provisioned Authenticode certificate and HTTPS timestamp service. Missing required credentials fail the build; default development mode explicitly reports UNSIGNED. No certificate was purchased/imported, no private key was created, no public-key trust was silently enrolled, and no existing release was re-signed. Keep all private PEM/PFX/KEY files out of the installer and repository.
